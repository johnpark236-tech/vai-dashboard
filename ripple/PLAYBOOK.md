# VAI-RIPPLE 일일 가상매수 절차서

매일(평일) 장 마감 후 실행하는 작업의 절차다. 이 문서대로 정확히 수행한다.
저장소: `johnpark236-tech/vai-dashboard` / 대시보드: https://johnpark236-tech.github.io/vai-dashboard/ripple/

## 0. 준비
1. 저장소를 push 권한으로 연결하고 클론한다. `git pull --rebase origin main` 으로 최신화.
2. 오늘 날짜(KST)를 확인한다. 토·일·공휴일(한국 증시 휴장)이면 매수 없이 종료한다.
3. `ripple/data/trades.json` 에 오늘 `buyDate` 기록이 이미 있으면 4단계(보고)만 수행한다.

## 1. 뉴스 수집과 사건 선정
1. 웹 검색으로 **오늘과 어제** 한국 주요 뉴스를 넓게 수집한다 (사회·재난·안전·보건·정책·규제·산업 사고·국제 사건 등, 서로 다른 검색 6회 이상).
2. VAI-RIPPLE 관점으로 후보 사건을 3개 이상 추린다: 사회적 사건 → 필수 수요/의무화/예산 → 간접 수혜.
   단순 실적·증권사 리포트·정치 테마·이미 급등한 테마 추격은 제외한다.
3. 사건 점수(70점 만점: 강도·지속성·정책 연결·수요 필연성·시장 미반영·검증 가능성)로 가장 높은 사건 1개를 고른다.

## 2. 종목 선정 (1종목)
1. 사건의 인과경로를 쓰고 수혜 후보 종목을 3~5개 찾는다.
2. **종목 검증은 반드시 검색·페이지 확인으로 한다. 기억에 의존 금지.**
   - 종목코드 6자리, 시장(KOSPI/KOSDAQ), 현재 상장·거래 여부를 실제 페이지에서 확인.
   - 확인 예: `https://stockanalysis.com/quote/kosdaq/<코드>/` 또는 `/quote/krx/<코드>/`, 네이버·다음 금융 검색 결과.
   - 회사명과 코드가 일치하지 않거나 비상장이면 탈락.
3. 하드필터: 거래정지, 관리종목·투자경고, 자본잠식, 감사의견 거절, 상장폐지 사유, 횡령·배임 수사 중 — 하나라도 해당하면 탈락.
4. 기업 점수(30점 만점: 사업 연결도·매출 비중·재무 안정성)를 매기고, 총점(사건+기업)이 가장 높은 **1종목**을 고른다.
   - 최근 60건 안에 이미 매수한 종목은 제외한다.
   - 80점 미만이어도 하루 1종목 매수 원칙에 따라 최고점 종목을 매수하되, `risk` 에 "기준 미달 매수"라고 적는다.

## 3. 기록과 업로드
1. 아래 형식의 JSON 파일을 만들어 `python3 ripple/scripts/add_trade.py <파일>` 로 추가한다 (직접 trades.json 을 손으로 고치지 않는다).
```json
{
  "buyDate": "YYYY-MM-DD (오늘, KST)",
  "code": "6자리", "name": "종목명", "market": "KOSPI|KOSDAQ",
  "sector": "섹터 (예: 정보보안, 소방·방재, 에듀테크)",
  "newsDate": "YYYY-MM-DD", "newsTitle": "기사 제목", "newsUrl": "실제 기사 URL",
  "newsSummary": "뉴스 내용 3~5문장",
  "causepath": "사건 → … → 수혜 영역",
  "reason": "이 종목을 고른 이유 (사업 연결, 매출 근거) 3~5문장",
  "risk": "주요 리스크",
  "scores": {"event": 0, "biz": 0, "total": 0},
  "candidates": "검토했지만 탈락한 종목과 사유 한 줄씩"
}
```
2. `git add ripple/data/trades.json && git commit -m "ripple: YYYY-MM-DD 가상매수 <종목명>"` 후 `git pull --rebase origin main`, `git push origin HEAD:main`.
3. 푸시하면 GitHub Actions 가 종가로 체결가를 채워 `ripple/data/portfolio.json` 을 갱신한다.
   30초 간격으로 최대 6분간 `git pull --rebase origin main` 하며 portfolio.json 에 오늘 종목의 `entry` 가 생길 때까지 기다린다.

## 4. 카카오톡 보고 (나에게 보내기)
카카오톡 메모 도구(`mcp__PlayMCP__KakaotalkChat-MemoChat`, 필요하면 ToolSearch 로 불러온다)로 보낸다.
한 메시지는 **900자 이내**로 하고, 길면 번호(1/N)를 붙여 **여러 건으로 나눠** 모두 보낸다. 내용을 줄이지 않는다.

- **메시지 ① 오늘 매수**: 날짜, 종목명(코드)·시장·섹터, 매수가·수량·매입금액, 목표가(+120%)·손절가(-15%)·만료일, VAI-CAPE 점수
- **메시지 ② 뉴스 내용**: 기사 제목, 날짜, 내용 요약, 기사 링크
- **메시지 ③ 선정 사유**: 인과경로, 선정 사유, 리스크, 탈락 후보
- **메시지 ④~ 전체 보유 현황**: 합계(보유 종목 수, 총 매입금액, 총 평가금액, 평가손익·수익률, 실현손익)를 맨 위에 두고,
  종목별로 `종목명 | 섹터 | 매수가→현재가 | 매입금액 | 평가금액 | 손익 | 수익률` 을 한 줄씩. 수익은 🔴+, 손실은 🔵- 로 표시. 종목이 많으면 15종목 단위로 메시지를 나눈다.
- 오늘 익절·손절·기간만료로 매도된 종목이 있으면 **매도 알림** 메시지를 따로 보낸다.
- 마지막 메시지 끝에 대시보드 주소를 적는다.

portfolio.json 에 체결가가 아직 없으면 "체결가는 장 마감 데이터 반영 후 대시보드에서 확인"이라고 적고 나머지는 그대로 보낸다.
카카오톡 도구가 없으면 보고를 생략하고 그 사실을 최종 결과에 적는다.

## 5. 원칙
- 숫자(가격·금액)는 portfolio.json 값만 쓴다. 추정하거나 지어내지 않는다.
- 규칙(1천만원, +120%, -15%, 86일)은 `ripple/data/config.json` 에 있다. 임의로 바꾸지 않는다.
- `ripple/` 밖의 파일은 건드리지 않는다.
